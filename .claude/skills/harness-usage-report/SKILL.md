# harness-usage-report

Interactive HTML "Claude Code Usage Report" — session cost, token usage, efficiency, usage patterns, and burn highlights — sourced from Claude Code sessions (via `~/.agents/.harness-usage-report/state/stats.csv`) and Codex sessions (via `~/.codex/sessions/` and `~/.codex/archived_sessions/`). Self-contained HTML, no external libs, persisted at `~/.agents/.harness-usage-report/reports/report-<timestamp>.html` (mode 0600 on POSIX; a no-op on Windows/NTFS). Day/Month toggle. Full column list lives in `stats.mjs`; trailing statusline-fed columns are forward-only (0/blank for older rows), duration/turns/tool_calls backfill from transcripts. Trailing `est_cost_usd` holds a token-estimated cost for sessions with no billed `total_cost_usd` (no statusline); the report shows billed-else-estimated.

`SKILL_DIR` = this skill's directory. Runs via `node` (ships with Claude Code, on PATH). Fresh machine: install first — `node <SKILL_DIR>/scripts/stats.mjs install` (writes SessionEnd hook + creates dirs; see INSTALL.md).

## Steps

1. Render: `node <SKILL_DIR>/scripts/stats.mjs report`. The command first refreshes stats.csv from all Claude Code transcripts + any lingering cost-state snapshots (excluding the active session), plus Codex rollout JSONL files (from `~/.codex/sessions/` and `~/.codex/archived_sessions/`, or override via `CODEX_HOME` env var), then renders — no manual backfill needed. It also refreshes the OAuth usage snapshot (5h/7d gauges) best-effort each run when creds are present (`~/.claude/.credentials.json`) — a silent no-op when logged out or on network/auth failure (prior snapshot kept); no `USAGE_REPORT_OAUTH=1` needed for the `report` path. The mid-flight active session is skipped (its transcript/cost-state are incomplete); everything else is brought current. **Active-session detection** (Phase I): a session is active iff its `cost-state/<sid>.json` is present and fresh (< 900s — the statusline rewrites it per render, so a recent one = live; this tolerates a mid-session pause that the old 180s transcript-mtime window mislabeled as closed). `record` deletes cost-state at SessionEnd, so a stale lingering cost-state (crash/hook-missed) is folded in, not excluded. Falls back to the 180s transcript-mtime window only when no cost-state exists at all (no statusline wired). Codex sessions have no cost-state or hook — ingestion is a batch scan of rollout JSONL files, folding subagents/forks into their parent session, with token counts and models extracted per API call.
2. Script writes the report, prints its absolute path, and auto-opens it in the OS default browser (`USAGE_REPORT_BROWSER=firefox|chrome|...` to override). If browser launch fails, the path is still printed — open manually.
3. Manual `backfill` rebuilds from all transcripts unconditionally — escape hatch for after migration or a corrupted stats.csv. Run while no Claude Code session is active.

Live capture is automatic via the SessionEnd hook (`stats.mjs record`): reads the full statusline JSON snapshot from `~/.agents/.harness-usage-report/state/cost-state/<sid>.json` (written verbatim by your statusline — last write per session wins) for cost/duration/lines/rate-limits/context, plus tokens/turns/tool_calls/last_model + transcript facets (tool mix, errors, subagents, skills, project cwd/branch, compactions → `facets_json`) from the session transcript JSONL. Also appends raw statusline JSON to `~/.agents/.harness-usage-report/state/sessions.jsonl` (archive) and deletes the cost-state file. No manual step for new sessions.

### Rate-limit forecast

`report` also fits an empirical-Bayes rate-limit forecast (claumon MODEL v2.1 port, `scripts/forecast.mjs`) shown in the "Rate-limit forecast at reset (Claude models only)" card. Per gauge (5h / 7d) it projects utilization at the reset boundary with an 80% credible interval (monotone Gamma-process MC) + ETA-to-100% and ETA-to-80%. Input is the OAuth usage-snapshots series (`state/usage-snapshots.jsonl`, grouped by normalized `resets_at` into completed windows + the open window); when OAuth polling is off it falls back to a **prior-only** view from the statusline `rl_5h_pct`/`rl_7d_pct` series (rate prior + n windows, no projection — no live window to project without `resets_at`). Fit persists to `~/.agents/.harness-usage-report/state/forecast.json`, lazy-rebuilt when stale (>7d or a newer transcript landed); `stats.mjs forecast [--force]` prints/forces the fit. Empty-state when <2 rl-bearing windows. Needs ≥2 completed windows + an open window for a full projection — run `fetch-usage --oauth --save` periodically (a few times per window) to accumulate them.

### Window balance (5h:7d exchange rate)

The "5h-window to 7d-window rate (Claude models only)" card answers *how much 5h-window capacity one unit of weekly budget costs*: `r = Σ Δ5h% / Δ7d%` measured **inside one 7d reset window**, plus the two readable forms — `1 day of weekly budget = r·5/7 hours of 5h capacity` and `one full 5h window = 7/r days of weekly budget`. Computed server-side in `stats.mjs` (`_window_balance`, persisted into `forecast.json` as `windowBalance`), drawn client-side (`svgWindowBalance`/`renderWindowBalance`). Range-independent — keyed to rate-limit reset windows, not the date picker, so it renders **before** the empty-range bail in `render()` and is deliberately absent from that function's reset-id list.

- **Bucket = the 7d reset window, never a calendar day/week.** A day carries too little Δ7d to divide by (the gauge is 1%-granular — measured day-level ratios spread p10 0.95 / p90 8.0, i.e. noise); a calendar week straddles the reset boundary and splits one window's burn across two points. Windows come from `_gauge_windows(snaps,'seven_day')`, so they inherit the `_normalize_reset_at` minute-rounding that merges the API's `16:59:59.9` / `17:00:00.0` jitter into one key.
- **r is a plan constant, not a behaviour metric** — structurally `L7/L5`, the ratio of the two budget sizes. The trend is a *step detector*: a shifted level means the plan changed, Anthropic re-tuned limits, extra-usage kicked in, or (once Anthropic populates `seven_day_opus`/`seven_day_sonnet`) the weekly gauge started weighting models differently. Day-to-day wiggle is estimator noise, not signal.
- **Δ pairing is deliberate**: `Δ7d = last − first` over the *observed* span (7d is monotone inside a window) paired with the 5h windows that **opened inside that same span** — each 5h window rose from 0 to its peak, so its own `uFinal` *is* its delta. Dropping the window's unobserved head from both sides keeps the ratio consistent instead of inflating one leg.
- **Every r is a lower bound.** An unobserved 5h window contributes 0 to `Σ Δ5h` while its usage still lands in `Δ7d`, so sparse polling pushes r *down*. `coverage` = share of the **nominal** 7d window sitting within 5h of a snapshot (nominal, not observed-span — else two snapshots a minute apart would score 1.0). Gate for the pooled all-time ratio: `coverage ≥ 0.5` **and** `Δ7d ≥ 20`. When nothing gates in, the card falls back to the **single best-covered window** — not a pool of every window, since a barely-observed window's near-zero `Σ Δ5h` against a real `Δ7d` drags the ratio down harder than it informs it — and labels itself `ungated` + "Lower bound".
- **Secondary statusline series** (faint dashed, always hollow, never gated): reset-aware deltas over the per-session `rl_5h_pct`/`rl_7d_pct`, bucketed into 7d bins anchored on the newest OAuth reset. Ordered by `ts`, which is the session **end** (`ts − start_epoch ≈ duration_ms`) — the order the gauges were actually read in; ordering by `start_epoch` mis-sequences parallel fleet sessions, reads each dip as a window reset, and inflates `Σ Δ7d` past the 100%/window ceiling. It exists so the card has a trend shape before OAuth history accumulates; it reads lower than the OAuth series because it only samples at session end.
- **Non-Claude models get no row in *this* ratio.** glm/other proxy-routed models draw zero Anthropic quota — no 5h/7d gauge for them, and their `rl_*` reading is just the ambient Claude value. Ollama cloud is the exception: it runs its **own** 5h/7d account quota (keyed `session`/`weekly` in `ollama-usage.jsonl`, what its settings page calls them), sampled independently by the daemon and rendered as its own set of cards — a separate quota, so it's still excluded from the Claude 5h:7d rate above. The honest analogue for models with no gauge at all is shadow quota (their Mtok × the Claude `%7d/Mtok` from Token yield), i.e. weekly budget *avoided*, not consumed.
- Trend readability needs ~8 windows. `stats.mjs forecast` prints the pooled ratio, both derived forms, and the per-window table (with coverage + exclusion reason).

### Burn highlights

The "Burn highlights" section (near the top of the report) names the top reasons your tokens burned in the currently selected timeframe (7d / 30d / all — the range picker). It's entirely client-side: `app.js` scores 4 candidate drivers (heavy-session concentration, outlier sessions vs. your all-time median, context compactions, long/high-turn sessions) against the sessions in the selected range, then shows the top 3 as cards, badge (high/med/low) reflecting each driver's severity. Recomputes on every range change, unlike the rest of the report's static sections.

## Capture contract (statusline)

Hard requirement for live cost/duration/lines/rate-limit/context capture: **your statusline must write the raw statusline JSON payload (the stdin it receives) to `~/.agents/.harness-usage-report/state/cost-state/<session_id>.json` on each render** — last write per session wins (≈ final snapshot). A cross-platform statusline ships at `<SKILL_DIR>/scripts/statusline.mjs` (model, context-usage bar, cost, rate limits, dir, worktree, git status). `install --with-statusline` copies it into `~/.claude/` and wires the `statusLine` setting to `node "<path>"` (skipped if you already have a statusLine command — add the file write to your own statusline instead). Optional: without it, `record` exits early and the report renders from transcripts only (cost/duration/lines/rate-limits blank, populated once a statusline is wired).

## Conventions

- **Token-legend pills** (Token Economics) filter the bar chart with **solo/deselect** semantic, not independent per-pill hide/show: empty `TOK_ACTIVE` = all series visible; click a pill → solos that series; click again → drops it, back to all when set empties; `All` resets. `tokVis()` returns `Array.from(TOK_ACTIVE)` (or all keys when empty) — must be an array, not a Set (`tokenBars` calls `.indexOf`). Do not change to independent-toggle without an explicit ask.
- **Token-yield pills** (Rate-limit section, "Token yield per rate-limit %") reuse the same solo/deselect pill semantic (`TY_ACTIVE`), filtering per-model lines. Metric = **Mtok per 1% of the 5h/7d window**, computed from per-session gauge **deltas** (drop = window reset, delta = current pct), aggregated `Σtok/Σdelta%` — NOT `tok/cumulative-pct` (r5/r7 are account-global cumulative gauge readings, so a raw ratio is meaningless). **One harness at a time** (`tokenYield(S,gk,hn)` filters on `harness(s.model)===hn`): r5/r7 is that harness's own account quota, so mixing harnesses would compare unrelated draws and break the delta chain. 7d/5h/`7d (codex)` toggle (`showTY`), default 7d Claude; the codex option reads codex rows' own `rl_7d_pct`. All client-side in `app.js` (`tokenYield`/`svgTokenYield`/`renderTY`); no stats.csv column added. A third toggle (`ollama wk`) swaps the same chart to ollama's own weekly-window yield — computed server-side (`stats.mjs _ollama_token_yield`) since it needs the scrape's per-model request deltas, not per-session gauge deltas; see the Ollama Cloud section below.
- **$/hour** — no per-session duration cap (legit sessions can exceed 8h); only the `$0`-cost filter drops idle/hung sessions.
- **$/line**, **lines / session**, **lines / hour** — computed over sessions with line data only (those reporting `lines_added` or `lines_removed`). Codex rows carry no line data; including them understates these metrics. `$/line` gated at 5% line-coverage (`LINE_COV=0.05`); below shows `—`.
- **Window balance** (`windowBalance` in `forecast.json`) is the 5h:7d exchange rate — see the section above for the estimator, the coverage gate, and why the bucket is the 7d reset window. Do not re-bucket it per day/week or pool ungated windows without an explicit ask.
- **Rate-limit panel** (5h/7d) is forward-only from the statusline `rate_limits` field (Claude Code v2.1.80+, Claude.ai Pro/Max only — absent for API-key/Bedrock/Vertex and some Max 20x oauth users). Empty-state notice when no rl-bearing sessions; `rl_5h_pct`/`rl_7d_pct` are floats, read with `_fnum` (not `_inum`), displayed `toFixed(1)`. Capped `>=99.5` (float noise), near-cap `>=80`. The **forecast card** beneath it (Phase D) projects each gauge to its reset boundary from OAuth usage-snapshots; projected values can exceed 100% (= demand past the window limit, model v2.1).
- **Harness filter** — the report filters by harness (Claude Code / Codex CLI / Proxied / Ollama), shown as pills in the controls bar next to the date-range presets. Harness is **derived from the model id string** — not a CSV column (no `source` column, no migration), so all existing sessions categorize automatically. `harness()` in `app.js`: `/^claude/` → claude, `/^(gpt-|codex)/` → codex (same test as `codex.mjs`'s `UNKNOWN_MODEL_RE`), else ollama/proxied. **Blank `last_model` → claude** is load-bearing, not a fallback: `renderOllamaTrend` feeds model-less synthetic rows to `svgRateTrend`, which now guards on `harness==='claude'`. The filter threads through `filterSessions`, so one predicate makes every section harness-aware; state persists across range changes.
- **Codex cost and quota**: Codex rows (discriminated by `last_model` = `gpt-5.6-sol`, `gpt-5.6-terra`, or `codex-auto-review`) appear in stats.csv alongside Claude and Ollama sessions with no source column. Cost is notional: Codex on ChatGPT Plus is subscription-billed (real marginal cost = $0), so `total_cost_usd` is blank for all Codex rows; `est_cost_usd` holds a per-call, per-model, long-context-tiered estimate at OpenAI API list rates (i.e., "what this would cost on the API"). `codex-auto-review` (Codex's internal review model) has no published rate and is priced at `gpt-5.6-terra` list rates as a deliberate proxy. Its usage is **split into its own row** per rollout (`session_id` = `<sid>:auto-review`, same `cwd`, no tool facets) rather than folded into the session's `last_model` — otherwise real auto-review spend is silently attributed to Sol/Terra. Split rows carry blank `duration_ms`/`turns`/`tool_calls`, so `$/hour` gates on `dur>0` as well as `cost>0`. Codex quota is 7-day only (sampled from rollouts into `codex-usage.jsonl` and rendered as its own set of gauge/forecast cards, separate from Claude's 5h/7d and Ollama's session/weekly quotas); there is no Codex 5-hour window. Degradation: missing `~/.codex` (any other machine, or Codex not installed) → zero Codex rows and no Codex cards, silently.
- All rendering client-side: report embeds `var SESSIONS=[...]` JSON + a JS IIFE that aggregates and renders every section; date-range controls re-filter → re-aggregate → re-render.
- **Pricing** (`PRICE` in `stats.mjs`, $/MTok `[input, output, cache_read, cache_create]`): base rates verified against claude.com/pricing#api (Opus 4.8 $5/$25, Sonnet 5/4.6 $3/$15, Haiku 4.5 $1/$5, Fable 5 $10/$50; cache_read=0.1×, cache_create-5m=1.25×). Resolved layered (Phase F, lowest→highest): embedded `PRICE` → `state/pricing-cache.json` (if <24h, from `fetch-pricing --oauth`) → `PROMOS` (time-bounded intro rates, in-window) → manual `state/pricing.json` override. **Sonnet 5 intro pricing ($2/$10) is reflected via `PROMOS` through 2026-08-31** (auto-expires). `stats.mjs fetch-pricing --oauth` (same `USAGE_REPORT_OAUTH=1`/`--oauth` gate as `fetch-usage`) pulls claumon's remote pricing.json, reduces model-ids to the skill's family keys (latest model-id per family), writes the cache; `stats.mjs pricing` prints the resolved table + which layer set each family. **GPT-6 Astra** (`gpt-6-astra`, released 2026-09-03) is priced at **$10/$50** short-context (cache_read $1, cache_create $12.50) and **$20/$75** long-context (cache_read $2, cache_create $25), with bare `gpt-6` as an Astra alias — Astra is the only GPT-6 tier, the generation dropped the Sol/Terra/Luna suffixes for a codename. All OpenAI rows were **re-verified against `developers.openai.com/api/docs/pricing` on 2026-09-04**, which corrected three stale entries: `gpt-5.6-sol` **$5/$30 → $4/$20** (long-ctx $10/$45 → $8/$30, repriced 2026-08-21) and `gpt-5.4-pro`'s long-context row **$30/$135 → $60/$270**. GLM rows re-verified against `docs.z.ai/guides/overview/pricing` the same day, adding **`glm-5.3` ($1.4/$4.4)** and **`glm-5.3-flash` ($0.075/$0.25, a 50%-off promo rate through 2026-09-09 UTC+8)**; cache-write stays 0 while z.ai lists cache storage as "Limited-time Free". `PRICE_ABOVE` is the long-context (>200k) tier mechanism; it holds the GPT-6 and GPT-5.6 families (+ `codex-auto-review`, which aliases terra) — ⚠️ OpenAI does not publish where Astra's tier starts within its 1,050,000-token window, so it reuses the global 200k threshold. No current Claude model has a >200k premium, and a Claude tier can be re-added via `pricing.json` if reintroduced. Estimated cost (`est_cost_usd`, sessions with no billed cost) folds in **subagent-run transcript tokens** (Phase G): each subagent-run transcript under `<project>/<sid>/**/*.jsonl` is summed per assistant message with `_msg_cost_tiered` (the long-context tier applies per request; subagent rows are `isSidechain` relative to the parent, so the sidechain skip is scoped to the main transcript only). Recomputed each backfill for no-billed sessions; billed sessions skip it (total_cost_usd wins). cache-create is not split 5m/1h (the breakdown isn't captured). Override rates without editing code via `<state>/pricing.json`: `{ "base": {"opus":[...]}, "above_200k": {"sonnet":[...]}, "long_context_threshold": 200000 }` (bare `{"opus":[...]}` map also accepted as base); only 4-number arrays honored, malformed files ignored.

## Scope & the harness-usage-report-suggestions skill

This skill: **collect, visualize** from local session-cost data (record + backfill stats.csv, render the HTML report). Deciding *what new insights to add* and *how to improve the report* belongs to the sibling **`harness-usage-report-suggestions`** skill. The report's "Usage roadmap" section is sourced from it: `report` shells out to `harness-usage-report-suggestions/scripts/improve.mjs roadmap --json` (resolved next to this skill; no hardcoded install path) and embeds the result (section omitted gracefully if that skill is absent). To add a metric/chart, invoke `/harness-usage-report-suggestions`.
